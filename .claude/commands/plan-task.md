---
description: 로드맵의 다음(또는 지정한) 작업을 구체적으로 구상하고 문서화한다
---

`docs/02_roadmap.md`를 읽고 다음 미완료(`[ ]`) 작업을 확인한다. 인자로 작업 번호/이름이 주어지면 그 작업을 대상으로 한다: $ARGUMENTS

1. 해당 작업의 범위를 **실제로 독립 검증 가능한 최소 단위**로 좁힌다. 너무 크면 사용자에게 분할을 제안한다.
2. 아래 항목을 채워 `docs/03_tasks/task-NN-<slug>.md`를 작성(또는 기존 파일을 갱신)한다:
   - 목표 (한 문장)
   - 입력 (API/파일/환경변수, 실제 소스 명시 — 가짜 데이터 금지)
   - 처리 로직 개요
   - 출력 (형식, 저장 위치)
   - 예외 처리 (API 실패, 빈 결과, 타임아웃 등)
   - 사용할 라이브러리/API — **표준 라이브러리로 되는지 먼저 검토**, 새 의존성이 필요하면 왜 stdlib로 안 되는지 명시
   - 검증 기준 (실제 데이터로 무엇을 확인하면 통과인지, 체크리스트 형태)
3. 코드는 아직 작성하지 않는다. 문서를 쓴 뒤, 사용자에게 이 구상으로 구현해도 될지 확인을 요청하고 멈춘다.
4. 컨펌 전에는 `docs/02_roadmap.md`의 체크박스를 바꾸지 않는다.
