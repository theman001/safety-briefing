대상 작업: $ARGUMENTS (없으면 가장 최근에 구현한 작업)

1. 해당 작업의 `docs/03_tasks/task-NN-*.md`에 적힌 검증 기준을 읽는다. 대상 코드는 아직 `test/` 폴더에 있다 (코드 위치 규칙: 검증 전 파일은 루트로 옮기지 않음).
2. **실제 외부 API/뉴스/공공데이터**로 `test/` 안의 코드를 실행한다. 샘플/목(mock) 데이터로 대체하지 않는다. 필요한 API 키가 없으면 사용자에게 요청하고 멈춘다.
3. 실행 결과를 다음을 포함해 요약 보고한다:
   - 호출한 실제 소스/건수
   - 핵심 출력 샘플 (예: 분류된 기사 몇 건, 분류별 개수, 요약문 예시)
   - 예외/실패가 있었다면 그 내용과 원인 추정
   - 가능하면 메모리/실행시간 (1GB RAM 제약과 비교해 여유가 있는지)
4. 검증 기준 체크리스트 각 항목에 대해 통과/실패/보류를 표시한다. 코드는 이 단계에서 고치지 않는다 — 수정이 필요해 보여도 먼저 사용자 피드백을 받는다.
5. 보고 후, 통과/수정 필요 여부를 사용자에게 묻고 다음 단계를 기다린다:
   - 수정 필요 → `/reflect`로 진행 (코드는 `test/`에 그대로 둔다)
   - 통과 + 사용자 승인 → 해당 파이썬 파일을 `test/`에서 프로젝트 루트로 옮기고, `docs/02_roadmap.md` 체크박스를 갱신한다.
