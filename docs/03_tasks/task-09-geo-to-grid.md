# Task 9. 위치 설정 유틸리티 (주소 → 기상청 격자 nx/ny)

상태: **실데이터 검증 통과, 승인됨(2026-11-17) → `geo_to_grid.py` 프로젝트 루트로 이동 완료.** 작성일 2026-11-17.

## 배경
Task 8a(날씨 수집)는 `WEATHER_NX`/`WEATHER_NY`(기본값 서울 60/127)를 `.env`에서 읽는다. 사용자가 다른 지역으로 바꾸려면 주소 → nx/ny 변환이 필요한데, 이건 일일 파이프라인이 아니라 설정을 바꿀 때만 쓰는 1회성 도구다.

## 목표
주소를 입력하면 기상청 단기예보 격자(nx, ny)를 출력한다.

## 입력
- 대화형 `input()`으로 주소 문자열 입력 (지번/도로명 구분 없음 — 카카오 로컬 API가 둘 다 같은 엔드포인트에서 처리)
- 환경변수: `KAKAO_REST_API_KEY`

## 처리 로직
1. 카카오 로컬 API(`GET https://dapi.kakao.com/v2/local/search/address.json`)로 주소 → 위경도(WGS84) 조회
2. 기상청이 공개한 Lambert Conformal Conic 변환식으로 위경도 → nx/ny 계산 (순수 수학, 외부 API 불필요)
3. `nx : nnn` / `ny : NNN` 형식으로 stdout에 출력, 나머지 진단 정보(매칭된 주소, 위경도, 다중매칭 경고)는 stderr로 분리

## 출력
- stdout: `nx : <정수>`, `ny : <정수>` 두 줄만
- stderr: 매칭된 주소, 위경도, (검색결과 2건 이상 시) 다중 매칭 경고

## 예외 처리
- `KAKAO_REST_API_KEY` 없음 → 즉시 종료(exit 2)
- 주소 검색 결과 0건 → 추측하지 않고 에러로 종료(exit 1), 더 구체적인 주소 요청
- HTTP 429/5xx/타임아웃 → 지수 백오프 재시도 최대 3회(`naver.py`/`accident_stats.py` 패턴)
- 검색결과 2건 이상(주소 모호) → 1번째 결과를 쓰되 stderr에 경고 표시(추측을 숨기지 않음)

## 사용할 라이브러리
- `urllib.request`, `urllib.parse`, `json`, `math` — 표준 라이브러리로 충분. 지오코딩만 외부 API(카카오) 필요, 위경도→격자 변환은 순수 수학이라 새 의존성 없음.

## 검증 기준 (실데이터) — 전부 통과 (2026-11-17)
- [x] 카카오 로컬 API 실제 키로 호출 성공 (앱에 "카카오맵" 제품 활성화 필요했음 — 최초 403 `OPEN_MAP_AND_LOCAL disabled` 발생 후 사용자가 콘솔에서 활성화)
- [x] 도로명 주소("서울특별시 중구 세종대로 110") → nx=60, ny=127 — Task 8a가 이미 실데이터로 검증한 서울 기본값과 정확히 일치
- [x] 지번 주소("서울특별시 중구 태평로1가 31", 위 도로명 주소와 동일 건물의 실제 지번) → 동일하게 nx=60, ny=127 — 지번/도로명 구분 없이 처리됨을 확인
- [x] 다른 지역(부산시청, "부산광역시 연제구 중앙대로 1001") → nx=98, ny=76 — 서울 외 지역에서도 정상 동작
- [x] 메모리/시간 측정 — peak RSS 약 26~28KB대(실제로는 KB 단위 표기로 약 26MB), 0.2초 (1GB 제약에 전혀 문제없음)

## 버그 발견·수정 (2026-11-17) — 격자 변환 라운딩 상수
구현 초기 "서울시청 = nx 60,ny 127"이라고 가정하고 테스트를 작성했으나 실행 결과 (61,128)이 나와, 가정이 틀렸을 가능성과 수식 버그 가능성을 구분해야 했다.
- **진단**: 기준점(OLAT=38.0, OLON=126.0)은 정의상 역산하면 정확히 (XO=43, YO=136)이어야 하는데, 실제로는 (44,137)이 나와 라운딩 상수(`int(x+1.5)`)가 틀렸음을 확인. 역변환(grid→latlon) 수식을 별도로 구현해 5개 좌표로 라운드트립 검증한 결과도 전부 1씩 밀려 있었음.
- **수정**: 라운딩 상수를 `+1.5` → `+0.5`로 변경. 수정 후 기준점 역산이 정확히 (43,136), 라운드트립 5건 전부 일치, 서울시청도 (60,127)로 기존 검증값과 일치.
- **교훈**: "알려진 값일 것"이라는 가정(추측)을 외부 사실로 오인할 뻔했던 사례 — 역변환 라운드트립처럼 자기 자신으로 검증 가능한 수학적 불변식을 우선 활용해 추측 없이 버그 소재를 좁혔다.
