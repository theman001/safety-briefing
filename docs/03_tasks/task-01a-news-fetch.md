## 범위 제안
Task 1("뉴스 수집·1차 분류")이 한 번에 검증하기엔 범위가 넓어 두 개로 쪼갠다.
- **1a (이 문서)**: 수집 + 날짜 필터 + 중복 제거까지만. 분류 없음.
- **1b (다음)**: 1a가 만든 원시 기사 목록을 입력으로 받아 규칙 기반 1차 분류만 수행. 1a 검증 후 별도로 `/plan-task`.

이렇게 나누는 이유: 수집(외부 API 의존, 네트워크/날짜 이슈)과 분류(순수 텍스트 로직, API 불필요)는 실패 지점이 다르다. 분류 로직은 1a의 실제 출력이 있어야 "어떤 제목/요약이 실제로 들어오는지" 보고 설계하는 게 더 정확하다.

## 목표
네이버 뉴스 검색 API에서 "어제"(KST) 게시된 산업안전/설비사고 관련 기사 메타데이터를 업종별 검색어로 수집하고, URL 기준 중복을 제거한 원시 목록을 만든다.

## 입력
- **API**: NAVER API HUB 뉴스 검색 (`https://naverapihub.apigw.ntruss.com/search/v1/news`) — 기존 `naver.py`가 이미 이 자격증명으로 실제 호출에 성공한 이력이 있다고 가정(이전 probe ZIP 존재). 자격증명을 이미 보유하고 있다면 그대로 사용하고, 없다면 구현 직전에 알려달라.
- **인증**: `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET` — `.env` 파일(`dotenv_loader.py`로 로드, 커밋 금지)에서 주입. 둘 다 없으면 즉시 에러 종료(종료코드 2) — 대화형 입력 프롬프트는 두지 않음, cron 비대화형 실행 대비.
- **검색어(업종별, 초안 — 기존 작업 참고, 1a 검증 후 조정 가능)**:
  정유·석유화학 / 철강 / 비철금속 / 발전소 / 방산 / 반도체 / 자동차·설비보전, 업종당 1~2개 구체 쿼리
- **대상 날짜**: 기본 "어제"(KST), `--date YYYY-MM-DD`로 override 가능 (검증 시 과거 특정일 재현용)

## 처리 로직 개요
1. 업종별 쿼리마다 `sort=date`로 페이지 호출 (`display=100`), 응답의 `pubDate`가 전부 대상일 이전이 되거나 결과가 바닥나면 해당 쿼리 중단
2. 각 기사 `pubDate`를 KST로 변환 → 대상일과 다르면 버림
3. `originallink`/`link`를 정규화(canonical URL: 스킴/호스트 소문자화, www 제거, 트래킹 파라미터 제거)해 중복 판정 키로 사용 → 동일 키는 매칭된 쿼리만 합치고 1건으로 유지
4. **산업 맥락 1차 필터(재현율 우선)**: 제목 또는 요약에 업종별 키워드(정유·철강·비철금속·발전소·방산·반도체·자동차/설비보전 등) 또는 일반 산업현장 용어(공장/설비/정비/작업자/산재 등 — naver.py의 `INDUSTRY_TERMS`/`INDUSTRIAL_CONTEXT` 참고)가 **하나라도** 걸리면 통과, 전혀 없으면 드롭. 애매하면 통과시킨다 — 사고/안전 여부 같은 정밀 판단은 여기서 하지 않고 1b에 넘긴다. 드롭된 건수는 메타데이터에 남겨 필터가 과한지 나중에 검증 가능하게 한다.
5. 분류 레이블/점수 계산은 없음 — 필터를 통과한 기사의 title, description, link는 원문 그대로 보존

**1b와의 경계 계약**: 1a가 출력에 포함시킨 기사는 전부 1b가 받아서 반드시 하나의 레이블(INCIDENT_REPORT/FOLLOWUP/SAFETY_TREND/MAINTENANCE_TECH/REVIEW/EXCLUDED 중 하나)을 받는다 — 1b 단계에서 "애매해서 스킵"은 없고 REVIEW로 보류한다. 즉 "진짜 무관한 기사 제거"는 1a(거친 키워드 필터)와 1b(정교한 분류, 여기서도 EXCLUDED 가능) 두 단계에 걸쳐 이루어지며, 1a는 느슨하게, 최종 판단은 1b가 한다.

## 출력
- `output/news_raw_<date>.json` — 산업 맥락 필터를 통과한 기사 목록 (title, description, originallink, link, canonical_url, published_kst, matched_queries, matched_industry_terms) — 1b의 입력
- `output/news_raw_<date>_meta.json` — 쿼리별 호출 성공/실패, raw 건수, 대상일 필터 후 건수, 중복 제거 건수, **산업 맥락 필터 통과/드롭 건수**, peak 메모리(RSS), 실행 시간

## 예외 처리
- 자격증명 누락 → 즉시 에러 종료(종료코드 2), cron에서 바로 실패가 보이도록
- HTTP 429/5xx → 지수 백오프 최대 3회 재시도
- HTTP 4xx(인증 오류 등) → 해당 쿼리만 실패로 기록하고 나머지 쿼리는 계속 진행
- 응답 JSON 파싱 실패 → 해당 쿼리만 실패 처리, 전체 중단하지 않음
- 모든 쿼리 실패 또는 대상일 기사 0건 → 경고 로그 + 메타데이터에 명시(분류 단계로 넘어가지 않도록 표시)

## 라이브러리/API
전부 표준 라이브러리로 충분 (naver.py가 이미 증명함): `urllib.request/parse`, `json`, `datetime`/`email.utils.parsedate_to_datetime`, `dataclasses`, `re`, `os`, `time`. 메모리 실측은 `resource.getrusage(RUSAGE_SELF).ru_maxrss`(Linux, stdlib)로 peak RSS 확인 — 1GB 제약 검증에 필요하므로 새로 추가.
`.env` 로딩은 `dotenv_loader.py`(이 프로젝트 공용, 표준 라이브러리만 사용) — Task 2/4/5도 같은 방식으로 재사용.
