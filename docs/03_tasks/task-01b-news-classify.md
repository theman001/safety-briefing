## 처리 로직 개요
naver.py의 분류 아이디어(키워드 사전)는 참고하되, 중첩 if/elif + 사후 패치 방식 대신 **우선순위 순서대로 평가하는 규칙 리스트**로 재설계한다 (먼저 맞는 규칙이 이기고 끝):

1. 업종 특정 키워드(`INDUSTRY_TERMS`, 1a와 공유) 또는 일반 산업맥락 키워드 없음 → `EXCLUDED` ("산업 맥락 확인 불가")
2. 제목에 행정/정치/경영 키워드(`CIVIC_TITLE`, `BUSINESS_TITLE`) 있고 구체적 사고 키워드 없음 → `EXCLUDED`
3. 제목/요약에 훈련·시연 키워드(`EXERCISE`: 모의훈련/방재훈련/**방제훈련**/대응훈련/시연/가상상황 등 — 오늘 실데이터에서 "방제훈련" 누락 발견, 추가) 있고 실제 발생 단서 없음 → `SAFETY_TREND`
4. 제목에 사고 강도 키워드(`EVENT_STRONG`: 화재/폭발/끼임/추락/사망/숨져 등) 있음:
   - 후속 보도 단서(`FOLLOWUP`: 조사/송치/기소/재판/과거 등) 있으면 → `INCIDENT_FOLLOWUP`
   - 아니면 → `INCIDENT_REPORT`
5. 후속 보도 단서만 있고(사고 키워드 약하거나 없음) 산업 맥락 있음 → `INCIDENT_FOLLOWUP`
6. 안전/예방 키워드(`SAFETY`: 안전교육/점검/예방대책 등) → `SAFETY_TREND`
7. 정비기술 키워드(`TECH`: 예지보전/설비진단/고장예측 등) → `MAINTENANCE_TECH`
8. 그 외 산업 맥락은 있으나 위 조건에 안 걸림 → `REVIEW`

각 기사에 레이블과 함께 **근거(reasons, 걸린 키워드 목록)**를 남긴다 — 나중에 왜 이렇게 분류됐는지 추적 가능해야 함.
